# Invoice A4 + EDC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Patients and staff get an A4 invoice with letterhead, a status watermark, every payment with its method (incl. new EDC), and per-invoice-date package progress; the thermal receipt stays as is.

**Architecture:** A pure model in `src/lib/invoice-a4.ts` turns an invoice source plus package snapshots into an `InvoiceA4` view. `src/server/invoice-a4-store.ts` loads the source and computes package snapshots from the session ledger up to a per-invoice cutoff. A plain-CSS component (no MUI/Tailwind, like `ReceiptPaper`) renders it on a public `/invoice#code` page (same code as `/struk`) and an admin print route `/admin/tagihan/[id]/invoice`. EDC is a new `PaymentMethod` value that stores a clinic bank account as destination.

**Tech Stack:** Next.js 15 App Router + server actions, Prisma 7 + PostgreSQL, plain CSS print rules in `src/app/globals.css`, Vitest (unit `npx vitest run`, integration `npm run test:integration` on `sundy_test`), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-22-invoice-a4-design.md`

## Global Constraints

- Thermal receipt (`ReceiptPaper`, `/struk`, ESC/POS) keeps its layout (IA1); it only gains the EDC label and a "Lihat invoice A4" link on `/struk`.
- Letterhead (IA2): wordmark "Sun" (gold `#d4a017`) + "DY" (brown `#4a3c28`), `CLINIC_FULL_NAME` sub-line "Nutrition, Slimming & Wellness Clinic", invoice branch name + address, `WA ${CLINIC_WHATSAPP_DISPLAY}`, `IG @${CLINIC_INSTAGRAM}`, `sundyclinic.com`; gold rule under it.
- Watermark text/colour (IA3): `LUNAS` green, `DEPOSIT` orange (paid > 0, balance > 0), `BELUM DIBAYAR` grey (paid 0), `DIBATALKAN` red; status and payments are always current, package numbers per invoice date (IA6).
- Payment line copy (IA4a/b, IA12): `{tanggal} · Tunai` / `· QRIS` / `· Transfer bank ke {destinationLabel}` / `· EDC {destinationLabel}`; revoked payments never shown.
- Package line copy (IA5): treatment `"{used} dari {total} sesi terpakai · sisa {remaining}"`; goods `"{used} dari {total} {unit} diterima · sisa {remaining}"`; header `"{package name} · berlaku s.d. {dateLabel}"`.
- Public link (IA8, IA9): `/invoice#code`, same code, validity and rate limiter as `/struk`; cancelled → existing text `RECEIPT_CANCELLED_TEXT`; invalid → `RECEIPT_INVALID_TEXT`. Admin route needs `invoice:read`; drafts → 404.
- EDC (IA12, IA13): label `EDC`; requires a clinic bank account ("Pilih mesin EDC."); no sender fields; supplier payments keep `TUNAI`/`TRANSFER`/`QRIS` only.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A purchase invoice whose package is cancelled or extended **after** the invoice: its box still shows the numbers and expiry as on its date — Task 3 test.
2. A revoked payment: disappears from the invoice and the watermark recomputes (e.g. LUNAS → DEPOSIT) — Task 2 test.
3. Old invoices without any package lines/entries: no "Paket Anda" box, no crash — Task 3 test.
4. A long invoice printing on 2+ pages: table header repeats and the watermark is on every page (`thead { display: table-header-group }`, watermark `position: fixed` in print) — Task 4 asserts the markup/CSS hooks; checked by eye in Task 5.
5. EDC chosen without a machine, or EDC sent to the supplier payment action: rejected with a clear message — Task 1 tests.

**Interfaces:**
- Produces:
  - `loadInvoiceA4(invoiceId: string): Promise<InvoiceA4 | null>` (store; no auth).
  - `invoicePackageSnapshots(tx | prisma, invoiceId: string): Promise<InvoiceA4Package[]>`.
  - `getPublicInvoice(code: string): Promise<ActionResult<{ state: "VALID"; invoice: InvoiceA4 } | { state: "CANCELLED" } | { state: "INVALID" }>>` — same limiter/code checks as `getPublicReceipt`.
  - `getInvoiceA4(id: string): Promise<InvoiceA4 | null>` — `invoice:read`; FINAL and DIBATALKAN; draft → null.
- Snapshot algorithm (IA6, IA10):
  - packages = `PatientPackage` with `purchaseLine.invoiceId = I` ∪ those having a `PAKAI` entry whose `invoiceLine.invoiceId = I`; order by purchase date.
  - cutoff = max `createdAt` of entries whose `invoiceLine.invoiceId = I`, else `invoice.finalizedAt`.
  - per item: `remaining = Σ delta (createdAt ≤ cutoff)`; `used = −Σ delta of PAKAI/BATAL_PAKAI (createdAt ≤ cutoff)`; `total = item.sessions`.
  - expiry at cutoff = latest `PERPANJANG.newExpiresOn` with `createdAt ≤ cutoff`, else earliest `PERPANJANG.previousExpiresOn` with `createdAt > cutoff`, else `pkg.expiresOn`.
